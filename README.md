# AgroChat

AgroChat — экспериментальный AI-ассистент по агротематике, разработанный на Python с использованием локальной языковой модели и подхода Retrieval-Augmented Generation (RAG).

Проект объединяет семантический поиск по базе знаний и генеративную языковую модель. Перед генерацией ответа система ищет связанные с запросом материалы в локальной базе знаний и передаёт найденный контекст LLM.

> **Важно:** это публичная демонстрационная версия старого прототипа AgroChat. Она публикуется в первую очередь как пример архитектуры и моей работы с локальными LLM, RAG, векторным поиском и FastAPI. Проект не претендует на production-ready состояние или «лучшее качество» генерации.

## О публичной версии

Оригинальная версия проекта использует другую генеративную модель, которая не может быть опубликована в открытом доступе.

Поэтому в данном репозитории для демонстрации работы приложения используется публично доступная модель:

```text
Qwen/Qwen3-4B-GGUF
Qwen3-4B-Q4_K_M.gguf
```

Она является заменой оригинальной модели и не отражает качество генерации исходной версии AgroChat.

Обработка изображений в публичной версии также отключена. Оригинальный проект использовал отдельную модель компьютерного зрения, которую я не могу распространять вместе с открытым исходным кодом.

Таким образом, этот репозиторий следует рассматривать как демонстрацию архитектуры и программной реализации, а не как полную копию оригинальной системы.

## Возможности

В публичной версии доступны:

- локальная генерация ответов с помощью LLM;
- Retrieval-Augmented Generation (RAG);
- семантический поиск по агрономической базе знаний;
- векторизация текста с помощью Sentence Transformers;
- поиск ближайших документов через HNSW;
- FastAPI backend;
- простой веб-интерфейс чата;
- запуск без внешнего LLM API;
- возможность подключения собственного GGUF-файла модели.

## Архитектура

Упрощённо обработка запроса выглядит следующим образом:

```text
Пользователь
     │
     ▼
Web-интерфейс
     │
     ▼
   FastAPI
     │
     ▼
Обработка запроса
     │
     ├──────────────► База знаний
     │                    │
     │            SentenceTransformer
     │                    │
     │                  HNSW
     │                    │
     ◄──── найденный контекст
     │
     ▼
 Локальная LLM
     │
     ▼
    Ответ
```

База знаний хранится в текстовых файлах в формате:

```text
Вопрос | Ответ
```

Для поиска релевантной информации текст преобразуется в embeddings. Для быстрого поиска ближайших записей используется HNSW.

Найденные фрагменты базы знаний передаются генеративной модели в качестве дополнительного контекста.

## Установка

Рекомендуемая версия:

```text
Python 3.11
```

Клонируйте репозиторий:

```bash
git clone <URL-РЕПОЗИТОРИЯ>
cd AgroChat
```

Создайте виртуальное окружение.

### Windows

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### Linux / macOS

```bash
python3.11 -m venv .venv
source .venv/bin/activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

> Установка `llama-cpp-python` на некоторых системах может потребовать установленного C/C++ toolchain.

## Запуск

```bash
python main.py

http://localhost:8000
```

При первом запуске приложению может потребоваться время для загрузки моделей и построения векторного индекса.

## Генеративная модель

Production-модель оригинального AgroChat не входит в этот репозиторий и не распространяется публично.

Demo-версия использует Qwen3-4B GGUF исключительно для того, чтобы опубликованный проект можно было запустить и проверить.

При отсутствии модели приложение может загрузить demo-модель с Hugging Face.

Также можно указать собственную GGUF-модель через переменную окружения:

```text
MODEL_PATH
```

Пример для PowerShell:

```powershell
$env:MODEL_PATH="C:\models\model.gguf"
python main.py
```

GGUF-файлы не должны добавляться в Git-репозиторий.

## База знаний

Данные для RAG находятся в директории:

```text
data/
```

Основной формат:

```text
Вопрос | Ответ
```

При построении индекса данные преобразуются в векторные представления, после чего HNSW используется для поиска записей, семантически близких к запросу пользователя.

## Ограничения публичной версии

Этот репозиторий содержит старую демонстрационную версию проекта.

В частности:

- оригинальная генеративная модель заменена публичной demo-моделью;
- отключена работа с изображениями;
- отсутствует оригинальная модель компьютерного зрения;
- отсутствует production-инфраструктура;
- качество ответов demo-модели может существенно отличаться от оригинальной системы;
- код отражает состояние проекта на раннем этапе разработки и не претендует на современную или оптимальную реализацию RAG/LLM-систем.

Цель публикации — показать устройство проекта, подход к решению задачи и используемые технологии.
